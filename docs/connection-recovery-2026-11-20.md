# 连接恢复与分阶段排障（2026-11-20）

## 服务器已上线：同设备重连

截图中的同一设备持续每 30 秒续租，旧实现会将同设备再次发起的新连接拒绝为 `device_already_connected`。现允许已认证用户为自己拥有的同一设备原子替换连接令牌，不增加在线名额。旧心跳不能续租新连接，旧释放不能删除新连接；其他设备仍受普通会员 1 台、豪华会员 2 台的并发上限约束。托管密钥仍在撤销中的保护保持不变。

原始截图还包含节点列表请求超时。服务器对应时间段的后续节点请求正常返回 200，不能由截图认定节点服务一直故障，也不能将所有超时归因于名额冲突。

## 客户端 0.1.8 (24)：需要新版安装包

- API 的完整请求（建立连接、等待响应和读取响应体）限定 20 秒。超时主动中止请求，不接受迟到响应覆盖会话，按钮可恢复后重试。
- 系统状态读取限定 15 秒、隧道启动限定 60 秒，启动超时主动停止；断开限定 20 秒，避免无限等待原生回调。
- 尚未自动登记设备时允许点击连接并重试登记，失败显示设备错误，不永久灰掉按钮。
- 退出账号先主动释放名额，再注销，并取消租约续期和本地租约状态。
- Apple 扩展将 HTTPS 检查（1010）、隧道 DNS 应答（1011）、检查模块执行（1012）分开，保留节点地址解析（1009）、路由（1003）、核心（1005）和数据通道（1006）的原因。
- Windows 与 Android 分开检查模块执行失败和 HTTPS 检查失败；Windows 单独报告核心启动失败。Flutter 事件保留并翻译原生错误码。

| 显示错误码 | 出错环节 |
| --- | --- |
| API-NODES | 获取节点列表 |
| API-CONFIG | 获取设备专属节点配置 |
| API-LEASE-ACQUIRE / API-LEASE-RELEASE | 申请 / 释放在线名额 |
| DEVICE-REGISTER | 本机自动登记 |
| NODE-CONFIG-PENDING | 服务器尚未准备好节点配置 |
| VPN-NODE-DNS | 解析节点服务器地址 |
| VPN-HTTPS | 通过节点访问 HTTPS 测试站失败 |
| VPN-CHECK | 连通性检查模块未能执行 |
| VPN-TUN-DNS | 隧道启动后没有 DNS 应答 |
| VPN-ROUTES | 系统路由设置失败 |
| VPN-CORE | VPN 核心启动失败 |
| VPN-START-TIMEOUT / VPN-STOP-TIMEOUT | 系统隧道操作超时 |

HTTPS 检查失败并不证明所有网站均不可用，也不能单凭此码区分目标站限制、节点出站故障或网络过滤。后续应结合对应节点日志和具体错误码排查。

## 验证

- 本机独立 PostgreSQL：设备登记、同设备令牌替换、旧令牌续期拒绝、旧释放不影响新租约、普通/豪华并发上限通过。
- 支付回归及 USDT 防重放用例通过；`go test -race -count=1 ./cmd/26x-api` 使用独立设备、支付宝、USDT 数据库。
- Flutter 测试验证：TCP 建立后 HTTP 不响应仍会超时；同一客户端下一次请求成功；各错误阶段不同且不会显示未知原始密钥文本。
- Flutter 静态分析通过。Apple Swift 语法检查及 macOS/iOS 无签名正式编译通过。
- 当前正式服务器已包含连接名额修复；客户端改动和待签名构建不代表已安装在用户设备，也不代表已做此次真机 VPN 全流程验收。

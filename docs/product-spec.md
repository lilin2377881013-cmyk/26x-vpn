# 26x VPN — Product Requirements

## Product goal

Ship a reliable 26x VPN service with one account across iOS, macOS, Windows, and Android. Users can install the official client, sign in, choose a node, connect, and manage their devices. Operators can manage accounts, subscriptions, nodes, and service status without editing static client files by hand.

## Audiences

- **Subscriber:** wants a clear connection state, a quick server choice, and simple recovery when a connection fails.
- **Operator:** needs to grant/revoke access, inspect node health, and support users without seeing browsing destinations.
- **Owner:** controls product policy, plans, release channels, and administrator access.

## Client MVP

1. Sign-in and account status.
2. Change password, review registered devices, and revoke a device.
3. Home screen with connect/disconnect, live tunnel state, current node, and elapsed connection time.
4. Node list with protocol, region, and measured latency. A failed probe is shown separately from an active tunnel state.
5. Rule mode and full-tunnel mode; platform-native VPN permission flow.
6. Diagnostics that include app/core versions and sanitized error codes, never credentials or browsing destinations.
7. Accessible controls, dark/light themes, Chinese and English strings, and platform-appropriate layouts.

### Connection-state model

`disconnected → preparing → connecting → connected → reconnecting → disconnected`

`error` is a terminal result for the current attempt and includes a stable error code and a user-readable next step. A latency-probe failure must not overwrite a live tunnel state.

## Official site and customer portal

- Product overview and 26x visual identity.
- Platform downloads and installation guides.
- Service status, FAQ, support contact, privacy policy, and terms.
- Account sign-in, plan status, devices, and subscription/config refresh.
- A read-only account overview, active-device list, device revocation, and password change are now present in the web scaffold. Public registration, payments, and VPN configuration refresh are not implemented.
- Payment checkout is excluded until the business model and regional rules are decided.

## Admin console MVP

- Dashboard: active users, active devices, node availability, and recent operational events.
- Users: search, status, plan, device count, expiry, suspend/reactivate, and revoke all credentials.
- Devices: platform, label, last seen, created time, and revoke.
- Plans/subscriptions: create plans, assign or expire access, and view entitlement history.
- Nodes: endpoint metadata, protocol, region, status, health timestamp, and capacity.
- Audit log: actor, action, target, time, and redacted metadata.
- RBAC roles: owner, operations, and support. Support cannot view or export node secrets.

## Service rules

- Each device receives a distinct, revocable credential for each enabled protocol.
- Client configuration is generated by the control plane and tied to the signed-in account/device. Public static YAML/JSON files are only for temporary development.
- Browsing destinations and payloads are not stored. Usage accounting stores byte counters and a coarse time bucket only if required by the plan.
- Nodes accept control-plane commands using authenticated, encrypted transport. The website never receives node private keys.
- Every administrative mutation is audited and can be traced to an administrator account.

## MVP acceptance criteria

These criteria describe the intended release and are not all met by the current development scaffold. See `roadmap.md` for the implementation gates.

- A user can sign in, register a device, fetch its configuration, and see the configured node list.
- The client displays native tunnel state; no UI path can mark a tunnel connected without a successful native callback.
- Suspending a user or revoking a device prevents new credentials and schedules node-side credential removal.
- An operator can see node health and manage users/devices without reading their VPN secrets.
- Public pages and admin pages are usable on mobile and desktop widths.
- iOS archive configuration supports a signed IPA export when the owner supplies valid Apple signing and Network Extension entitlements.

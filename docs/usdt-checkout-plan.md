# USDT-TRC20 自建收款与支付选择页

状态：开发和隔离测试；未上线。生产启用必须完成以下验收，提供真实收款地址和价格配置，并完成小额主网支付验收。

## 用户流程

登录用户在现有客户端选择套餐后，服务器返回 26x HTTPS 支付选择页。用户选择支付宝后继续使用原通道；选择 USDT 后获得本笔订单的地址、完整六位小数金额、二维码和截止时间。客户端不改动。现有已发出的支付宝链接继续有效。

新通道默认关闭；只有显式启用并提供合法 TRC20 地址和完整定价时才启用选择页。不替换现有第三方收银台，也不获取钱包私钥。

## 订单识别

- 每笔订单绑定已登录用户和套餐快照；访客不能购买。
- USDT 用整数微单位保存、计算（1 USDT = 1000000 单位），不使用浮点金额。
- 完整金额的小数点后六位是付款识别码；代码按收款地址唯一预留，包含超时、已支付订单，永久不复用。
- 默认在报价上增加 0.000001 至 0.010000 USDT。恢复仅使用过该区间的整数报价钱包时，可在数据库指定新区间 010001 至 020000。付款方式选择页显示加价上限，转账页显示准确金额。
- 下单后锁定币种、网络、收款地址、价格和有效期。选择一种付款通道后不允许原订单切换通道，避免双通道重复付款。
- 不用付款钱包地址推断用户，不把用户提供的 TXID 当作到账证据。
- 同一地址下的所有整数套餐共用一个区间的 10000 个尾号。区间用尽后停止发单。备份须包含钱包区间和已发订单。
- 六位尾数是订单匹配信息，不是付款身份认证。如果用户填错尾数且碰巧等于另一张有效订单，仅凭链上金额无法判断本意，需要按争议流程核查。

## 到账确认

只接受 TRON 主网官方 USDT 合约 `TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t`。索引器的 TRC20 转账历史用于发现候选交易；再通过 SolidityNode 查询已固化的成功交易回执，解析 Transfer 日志，核对合约、收款地址、完整整数金额、订单创建时间和截止时间。确认前不发会员。

交易哈希和日志序号联合唯一，同一链上转账只处理一次。订单行与账号行加锁，记录链上证据和开通订阅放在同一数据库事务中；重复轮询、服务重启和并行扫描不会重复发放会员。

少付、多付、拆分支付、错误尾数、超时/迟到付款进入待核查记录，不自动猜测订单，也不自动凑单。完整记录原始交易金额、地址、哈希及匹配原因，后台可查看。人工补单必须审计，不能直接信任截图或付款人声明。

## 轮询与恢复

使用 TronGrid 主网 HTTPS 接口和服务端 API Key；接口访问失败、限流、返回不完整或回执未固化时重试，不判为已支付。分页必须全部扫描完成才能推进游标，并使用重叠扫描及事件去重。不得跟随 API 返回的任意外部链接。

监听器与网页独立生命周期，支持多个实例互斥处理和重启续扫；历史收款地址需继续监听或执行对账，不能换地址就丢弃旧订单。提供按交易哈希的链上补查能力。

## 验收与上线

1. 隔离 PostgreSQL 与模拟链接口验证：报价精度、地址校验、识别码并发冲突、超时不复用、正常到账、假币、假哈希、未确认/执行失败、金额错误、迟到款、多次重放、重启续扫、分页及限流。
2. 验证支付宝原有用例全部通过；选择页不提前创建支付宝通道订单；USDT 不可用时不开放新支付。
3. 网页检查手机/桌面布局、金额六位完整显示、二维码及网络提示；后台显示渠道、金额、收款地址、TXID、到账及会员发放状态。
4. 提供真实地址和价格后，执行主网只读连接检查，再做一笔用户授权的小额真实支付和重复扫描验证。测试通过才启用生产。
5. 保留完整备份、关闭新通道的开关及回滚步骤。关闭新下单不能停止已有 USDT 订单的到账监听；不能把真实支付测试结果伪装成模拟测试。

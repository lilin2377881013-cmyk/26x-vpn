# USDT 收银台测试记录

日期：2026-11-19。分支：`feat/usdt-cashier`。状态：未部署生产，新支付入口未启用。

## 已通过

- 独立本机 PostgreSQL 上的 `go test -race -count=1 -v ./cmd/26x-api` 支付用例：
  - 金额解析、整数微单位运算、精确换算及六位格式。
  - Base58Check 地址校验；错误校验和拒绝。
  - 固化回执校验：假代币、错误收款人、错误事件、零金额、无效数据、执行失败和回执缺失不发会员。
  - 选择页不提前请求支付宝；USDT 监控不健康时拒绝新支付。
  - 选择一种通道后锁定；支付宝初始化失败仍不能换为另一通道付款，支持同订单重试。
  - HTTP 路由、来源校验、支付令牌校验、禁止缓存、完整金额与地址、PNG 二维码。
  - 确认到账后一次开通；并行重放不重复发放；不同订单编码唯一；过期编码不释放。
  - 迟到转账进入 review，无法精确匹配的金额进入 unmatched。
  - 重建服务对象后重放不重复开通；模拟索引分页，不跟随外部 next URL；API 限流不推进游标。
  - 停止接收新订单后继续处理已有付款；人工链上补查有审计；后台返回收款与订单字段。
  - 填满 10000 个已过期尾数的测试夹具后，不能复用编码或扩大微调窗口。
- 原支付宝 `TestPaymentCheckoutAndNotification` 和 `TestCashierRedirect` 回归通过。
- `go vet ./...` 通过。
- 管理后台 TypeScript 检查、ESLint 和 Next.js 生产构建通过；未上传生产构建。
- 隔离收银台真实浏览器渲染：390px 手机和 1280px 桌面均无横向溢出，金额完整、二维码加载成功。
- 主网只读地址查询 HTTP 200、success=true；不代表已验证真实到账。

非支付的设备/试用/推广数据库用例未在这轮运行，未将其跳过结果表述为通过。
